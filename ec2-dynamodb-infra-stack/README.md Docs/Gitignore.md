Terraform-specific .gitignore

# Local .terraform directories
**/.terraform/*

# .tfstate files — contain sensitive data, never commit
*.tfstate
*.tfstate.*
*.tfstate.backup

# Crash log files
crash.log
crash.*.log

# Exclude variable files that may contain secrets
*.tfvars
*.tfvars.json
# Keep example/template files
!example.tfvars
!*.tfvars.example

# Ignore override files (local dev overrides)
override.tf
override.tf.json
*_override.tf
*_override.tf.json

# CLI configuration files
.terraformrc
terraform.rc

# Terraform lock file — DEBATE below
# .terraform.lock.hcl

# Plan output files
*.tfplan
*.plan


On .terraform.lock.hcl: commit this one. It pins provider versions for reproducible runs across your team/CI — don't gitignore it like some outdated guides suggest.

Why each matters
.tfstate files — contain full resource details including sometimes plaintext secrets (DB passwords, keys) depending on the provider. Should live in remote backend (S3), never git.
.tfvars — often holds account IDs, CIDR ranges, or secrets specific to your environment. Commit an example file instead.
.terraform/ — just downloaded provider binaries and modules, regenerated by terraform init.
